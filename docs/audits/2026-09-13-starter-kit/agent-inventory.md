## Proposed instruction hierarchy

1. Repository operating instructions: edit/commit/verification preferences and how to discover project guidance.
2. Current architecture and capability manifest: dependency direction, supported revisions/platforms, ownership rules.
3. Project workflows: create, adopt incrementally, upgrade, replace a provider and release.
4. Capability recipes: exact packages, runnable composition, native steps, app decisions, migrations and verification.
5. Product profiles and app-specific guidance: preferred providers, branding, event catalogue, entitlements and journeys.
6. Explicit legacy archive: old facade examples preserved for migration only.

The revamp should not blindly discard useful branding, backend or operational knowledge. Its purpose is to remove conflicting entry points and make current, supported recipes discoverable and executable.
