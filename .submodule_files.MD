# Submodule Commands & Instructions

Everything you need to set up and work with the project's git submodules. Copy commands from here when you need them.

## The submodules

| Path | Remote |
| --- | --- |
| `agents` | `git@github.com:silencio260/genrevibes-projects-skills.git` |
| `packages/genrevibes_starter_kit` | `https://github.com/silencio260/genrevibes_starter_kit.git` |

## What a submodule is (one line)

A pointer from this repo to a **specific commit** of another repo. The outer repo stores the pointer; the inner repo owns its files and history.

---

## `.gitmodules` (lives at the repo root)

```ini
[submodule "agents"]
	path = agents
	url = git@github.com:silencio260/genrevibes-projects-skills.git
	ignore = dirty
[submodule "packages/genrevibes_starter_kit"]
	path = packages/genrevibes_starter_kit
	url = https://github.com/silencio260/genrevibes_starter_kit.git
	ignore = dirty
```

`ignore = dirty` → the outer repo only flags a submodule when its **committed** SHA changes, not on every file edit inside. Use `ignore = all` to suppress SHA changes too.

---

## VS Code settings (so both repos appear in Source Control)

Add to `.vscode/settings.json`:

```json
"git.detectSubmodules": true,
"git.detectSubmodulesLimit": 20,
"git.repositoryScanMaxDepth": 3,
"git.autoRepositoryDetection": "subFolders"
```

Then reload the window: `Cmd+Shift+P` → "Developer: Reload Window".

## One-time setup commands

> Commit and push any in-progress work **inside** `agents/` and `packages/genrevibes_starter_kit/` first — these commands rewrite where each inner `.git` lives.

Run from the repo root:

```bash
# 1. Remove the existing gitlinks from the outer index (working tree stays put)
git rm --cached agents
git rm --cached packages/genrevibes_starter_kit

# 2. Re-add them as proper submodules. This:
#    - regenerates .gitmodules
#    - moves each inner .git directory into .git/modules/<name>
#    - replaces inner .git with a file pointer
git submodule add --force git@github.com:silencio260/genrevibes-projects-skills.git agents
git submodule add --force https://github.com/silencio260/genrevibes_starter_kit.git packages/genrevibes_starter_kit

# 3. Make sure .gitmodules has `ignore = dirty` on both entries
#    (open .gitmodules and add the line if missing — see template above)

# 4. Commit the new layout in the outer repo
git add .gitmodules agents packages/genrevibes_starter_kit
git commit -m "chore: register agents and starter kit as submodules"
```

## After a fresh `git clone`

The submodule folders will be empty. Populate them:

```bash
git submodule update --init --recursive
```

## Day-to-day commands

### Pull the latest commit inside each submodule and update the pointer

```bash
# Pull everything inside each submodule from its tracked remote branch
git submodule update --remote --merge

# Bump the pointer in the outer repo
git add agents packages/genrevibes_starter_kit
git commit -m "chore: bump submodules"
git push
```

### Check current submodule state

```bash
git submodule status
```

### Working inside a submodule

Just `cd` into the folder and use git normally — it's its own repo:

```bash
cd agents
git checkout main
# edit, commit, push as usual
git add .
git commit -m "..."
git push
cd ..

# Back in the outer repo, bump the pointer
git add agents
git commit -m "chore: bump agents submodule"
```

## Troubleshooting

**Outer repo shows file-level edits inside a submodule as unstaged changes.**
`ignore = dirty` is missing from `.gitmodules`. Open `.gitmodules` and add it under each `[submodule "..."]` block.

**`git submodule add` says "already exists in the index".**
You skipped step 1 above. Run `git rm --cached <path>` first.

**VS Code only shows one submodule, not both.**
Scan depth too shallow. Confirm the VS Code settings block above is in `.vscode/settings.json`, then reload the window.
